## 2. Root Cause Analysis of Regressions

### 2.1 The Metric Illusion: Target Overlap vs. Sørensen–Dice
The most prominent source of "perceived" regressions stemmed from the interpretation of `ants.label_overlap_measures`:
* **`MeanOverlap`** is the true **Sørensen–Dice coefficient**:
  $$\text{Dice}(A, B) = \frac{2 |A \cap B|}{|A| + |B|}$$
* **`TotalOrTargetOverlap`** is **Target Overlap (Recall/Sensitivity)**:
  $$\text{TargetOverlap}(A, B) = \frac{|A \cap B|}{|A|}$$

On the identical warped label for Mindboggle `mbhard` (Pair 44: `NKI-TRT-20-2` $\to$ `MMRR-21-2`):
* **Sørensen–Dice (`MeanOverlap`)**: **`0.5985`**
* **Target Overlap (`TotalOrTargetOverlap`)**: **`0.6321`**
* **Difference**: **`+0.0336` (+3.36% artificial inflation)**.

Historical ad-hoc scripts (`benchmarks/benchmark_deep_metrics.py`, `benchmark_barn.json`) logged `TotalOrTargetOverlap` under the label "Dice = 0.63+". When standard evaluators enforcing strict Sørensen–Dice were subsequently applied, scores appeared to drop by ~3.5%, creating the illusion of an algorithmic regression when in reality the mathematical definition had changed.

### 2.2 Silent Evaluation Configuration Dropping
In `src/syntx/benchmark/evaluate.py`, the model dispatcher attempted to look up model parameters via `config.get("params", {})`. Because `docs/provenance/run_config.json` stores configurations under model-specific keys (`syn_config`, `tvf_config`, `syngs_config`, `greedy_config`), `config.get("params", {})` returned an empty dictionary. Consequently, all tuned parameters in `run_config.json` were silently dropped, falling back to un-tuned inline defaults.

### 2.3 Dispatch to Suboptimal Smoothers
In `evaluate.py`, invoking `--model syn` routed execution to `regularizer="gaussian"`. This violated GEMINI.md Rule 3, causing under-convergence on smooth cortical images compared to the physical Sobolev Green operator ($\alpha = 1.5$).

### 2.4 Stale Disk Cache Pollution During `--resume`
The completion check `is_pair_completed()` in `scripts/run_90pairs.py` only checked whether `pair_XXX_{model}.json` existed and had `status == "SUCCESS"`. When hyperparameters or bug fixes were made, rerunning with `--resume` skipped pairs whose cached JSON files were generated by previous obsolete configurations, permanently preserving outdated results.

### 2.5 Single-Threaded CPU ITK Constraint Removed
`os.environ["ITK_GLOBAL_DEFAULT_NUMBER_OF_THREADS"] = "1"` was previously forced in `src/syntx/__init__.py` and `src/syntx/robust_affine.py`. This artificially restricted ANTs/ITK baselines to a single CPU thread. OpenMP multi-threading is now the active default across all CPU operations.

## 3. Anti-Regression System Architecture

### 3.1 Centralized Single Source of Truth (`syntx.benchmark.config`)
We created `src/syntx/benchmark/config.py`, which provides:
* **`DEFAULT_BENCHMARK_CONFIG`**: Canonical dictionary defining production parameters for all 4 models (`syn`, `syngs`, `tvf`, `greedy`).
* **`get_model_config(model, config)`**: Robust hierarchical parameter extractor with full fallbacks.
* **`compute_config_hash(config_dict)`**: Deterministic 16-character SHA-256 fingerprint generated from canonical JSON serialization with sorted keys.
* **`validate_config_compatibility(cached_hash, current_hash)`**: Strict validation verifying cache validity.

### 3.2 Automated Cache Invalidation
Both `src/syntx/benchmark/evaluate.py` and `scripts/run_single_pair.py` stamp `config` and `config_hash` into atomic JSON output files. `is_pair_completed()` in `scripts/run_90pairs.py` validates the cached hash against `expected_config_hash`. Stale results with mismatched or missing hashes are automatically invalidated and re-evaluated.

### 3.3 Automated Regression Test Suite (`tests/test_benchmark_regression.py`)
A comprehensive 15-test suite was added to `pytest`:
1. **Metric Math Invariants**: Strictly verifies that `compute_bidirectional_dice` computes Sørensen–Dice and rejects Target Overlap on asymmetric label sets ($p < 10^{-5}$).
2. **Config Invariants**: Asserts that `reg_iterations == [100, 100, 20]` across all models, and verifies locked parameters for `tvf` (`fast_smooth=False`, `step=0.50`, `dsti1`), `syngs` ($\alpha=0.35$, `step=0.20`, `sobolev`), and `syn` (`sobolev`, $\alpha=1.5$).
3. **Hashing Determinism & Sensitivity**: Asserts that changing any hyperparameter alters the SHA-256 hash, while key order does not.
4. **Cache Invalidation**: Confirms `is_pair_completed` rejects stale cache files.
5. **Multi-Model Convergence**: Tests fast synthetic 2D convergence for `syn`, `syngs`, and `tvf`.
6. **Permutation Invariance**: Asserts random order generation produces a complete, deterministic permutation of all 90 pairs.

## 4. Locked Production Parameters

### 4.1 `syntx.syngs` (Geodesic Shooting)
* **`alpha = 0.35`**: Prevents the 19× folding explosion seen when $\alpha$ is reduced to $0.20$ ($0.022\%$ vs $0.415\%$ folding).
* **`max_step_norm = 0.20`**
* **`regularizer = "sobolev"`**
* **`optimizer_lr = 1.0`**
* **`reg_iterations = [100, 100, 20]`**
* **`syn_metric = "cc2"`**

### 4.2 `syntx.tvf` (Time-Varying Velocity Fields)
* **`tvf_regularizer = "dsti1"`** (Dirichlet-Shield): Enforces $v(\partial \Omega) \equiv 0$, preventing boundary coordinate drift and guaranteeing $\min |J| > 0$.
* **`tvf_fast_smooth = False`**: Full-resolution filtering prevents over-smoothing fine gyral boundaries, delivering +1.5% higher Dice than downsampled smoothing.
* **`max_step_norm = 0.50`**: Optimal CFL bound for RegAdam.
* **`optimizer_lr = 1.2`**
* **`tvf_flow_sigma = 1.0`**, **`tvf_total_sigma = 0.035`**, **`dsti_alpha = 0.035`**
* **`reg_iterations = [100, 100, 20]`**
* **`similarity_metric = "cc2"`**

## 6. Population Benchmark Orchestrator Enhancements

In `scripts/run_90pairs.py`:
1. **Randomized Pair Order (`--random-order`, `--seed`)**: Pairs are evaluated in a reproducible pseudorandom sequence to avoid systematic cohort drift or bias during long runs.
2. **Deterministic Permutation**: Per-pair and cross-model summary reports automatically sort results by `pair_idx`, preserving canonical table ordering regardless of evaluation order.
3. **Live Progress Monitoring**: Generates real-time Markdown cross-model summaries at `results/multimodel_live_comparison.md` after each pair completes across all models.
